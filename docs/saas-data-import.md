# 기존 데이터 이관 — 운영팀 절차 (ops-import.mjs)

구독형 ERP 에 가입한 회사가 "예전에 쓰던 엑셀을 넣어 달라" 고 하면 **운영팀이 대신** 넣는다(사용자 결정 2026-10-20 — 화면으로 열지 않는다. AI 토큰 비용과 데이터 손실 걱정 때문). 매일 반복되는 쿠팡·스마트스토어 "오늘 주문" 가져오기는 화면(주문 관리 › 채널 주문 가져오기)에 있다 — 아래 3절.

## 1. 고객에게 받을 엑셀 양식 3종

첫 시트, 첫 행이 헤더. 헤더 이름은 아래 표의 **인식 이름 중 하나**면 된다(띄어쓰기·대소문자 무시, 포함돼도 인식 — "고객 연락처" 는 연락처로 잡힌다). 앞에 안내문 몇 줄이 있어도 헤더 행을 찾아낸다(마켓원장 export 처럼). 빈 행은 건너뛴다.

### 1-1. 고객 (`customers`)

| 칸 | 필수 | 인식 이름 | 비고 |
|---|---|---|---|
| 고객명 | ✔ | 고객명, 이름, 성명, 입금자명, name, customer | 앞뒤 공백 제거 |
| 연락처 | | 연락처, 전화, 휴대폰, phone, tel | 숫자만 남겨 010-1234-5678 꼴로 정규화. 9~12자리가 아니면 문제 행에 적고 그대로 넣음 |
| 닉네임 | | 닉네임, 별명, nickname, alias | 밴드·카톡 별명 |
| 주소 | | 배송지, 주소, address | |
| 상세주소 | | 상세주소 | |
| 메모 | | 메모, 비고, note, 특이 | |

중복 판정: **이름 + 연락처(숫자)** 가 DB 에 있으면 건너뜀. 파일 안에 같은 사람이 여러 줄이면 정보가 많은 쪽으로 합쳐 한 줄만. 정산 더미 행(쿠팡·Npay정산·KB1234… 같은 이름, `src/lib/patterns.js`)은 자동 제외.

### 1-2. 품번 (`products`)

| 칸 | 필수 | 인식 이름 | 비고 |
|---|---|---|---|
| 품번 | | 품번, 코드, code, sku | 비어 있으면 `next_product_code(접두어)` 로 새로 발급. 접두어는 회사 설정(productPrefix) → 없으면 `--prefix` → 없으면 LH |
| 원단명 | ✔ | 원단명, 원단, 품명, 상품명, 품목, name, fabric | |
| 색상 | | 색상, 컬러, 색, color | |
| 단위 | | 단위, unit | 비면 "마" |
| 단가 | | 단가, 판매가, 가격, price | 숫자. "12,000원" 도 읽는다. 못 읽으면 비워서 넣고 문제 행에 적음 |
| 메모 | | 메모, 비고, note | |

중복 판정: **품번(코드)** 이 같거나 **원단명 + 색상** 이 같으면 건너뜀(파일 안 중복도 같은 규칙). 롤(재고 수량)은 넣지 않는다 — 품번만 만들고 입고는 화면(재고 관리 › 입고)에서.

### 1-3. 주문 (`orders`) — 지난 주문 이력

| 칸 | 필수 | 인식 이름 | 비고 |
|---|---|---|---|
| 날짜 | ✔ | 주문일, 날짜, 일자, date | 엑셀 날짜·"2025-03-04"·"25.03.04"·"3/4"(올해) 모두. 오늘보다 미래면 작년으로(연도 없는 "12/30" 사례). 2000~2099 밖이면 문제 행 |
| 고객명 | ✔ | 고객명, 입금자명, 고객, 이름, 성명 | |
| 연락처 | | 연락처, 전화, 휴대폰, phone | 정규화 |
| 원단명 | ✔ | 원단명, 원단, 품명, 품목, 상품명, fabric, item | 한 행 = 품목 하나. 한 주문에 품목이 여럿이면 행을 나눠 적는다(각각 한 주문으로 들어간다) |
| 색상 | | 색상, 컬러, color | |
| 수량 | | 수량, 마수, qty | 0 이면 문제 행 |
| 단가 | | 단가, 입고가 | |
| 금액 | | 금액, 매출, 상품금액, amount | 0 이면 문제 행 |
| 배송비 | | 배송비, 운임비, 운임 | |
| 합계 | | 운임비포함매출, 합계, 총액, total | 비면 금액 + 배송비 |
| 결제 | | 결제, 입금, payment | "완료/입금/paid" 면 입금완료, 그 밖의 값은 미입금, **비면 입금완료**(지난 이력이므로) |
| 상태 | | 상태, status | "출고완료/완료/배송" → 출고완료, "포장" → 포장완료, 그 밖은 접수, **비면 출고완료** |
| 배송지 | | 배송지, 주소 | |
| 담당자 | | 담당자, 담당 | 이름 문자열 그대로(담당자 표와 맞추지 않는다) |
| 판매처 | | 판매처, 채널 | 쿠팡·스마트스토어 등. 밴드는 비움 |
| 메모 | | 메모, 비고 | |

중복 판정: **날짜 + 고객 + 원단명 + 수량 + 금액** 지문이 DB 의 어느 주문 품목과 같으면 "이미 있음" 으로 건너뜀. 파일 안에 같은 지문이 두 번 있으면 **둘 다 넣고** 문제 행 목록에 적는다(같은 걸 두 번 산 경우가 있어서 — 운영자가 보고 판단). 입금완료 주문은 금액만큼 `payment_logs` "입금"(메모 "엑셀 이관 일괄입금")을 함께 넣어 정산 화면의 매출에 잡힌다. 모든 행에 `time = "00:00"` 을 남긴다(옛 ExcelImport 와 같은 표시) — 이게 "이관분" 표시이고 되돌릴 때 쓴다.

## 2. 절차

```
node ops-import.mjs <login_id> customers|products|orders <파일.xlsx> [--sheet 이름] [--apply] [--prefix LH]
```

1. **dry-run**(기본): `node ops-import.mjs testco customers 고객.xlsx`
   - 회사 확인(company_accounts.login_id → owner_id), 컬럼 매핑 표, 넣을 건수·건너뛸 건수·문제 행 목록, 앞 5건 미리보기를 찍고 **아무것도 쓰지 않고** 끝난다.
   - 필수 칸을 못 찾으면 헤더 목록을 보여주고 멈춘다 → 고객에게 헤더 이름을 양식에 맞춰 달라고 하거나 운영자가 엑셀에서 헤더만 고친다.
2. **확인**: 매핑 표가 맞는지(특히 금액·단가·합계가 서로 바뀌지 않았는지), 문제 행이 고객이 고쳐야 할 것인지(날짜·금액 누락) 본다. 넣을 건수가 고객이 말한 숫자와 비슷한지 본다.
3. **apply**: 같은 명령에 `--apply`. 고객·주문은 100건씩, 품번은 한 건씩(품번 발급 때문) 저장한다. 중간에 실패하면 "n/m 건까지 들어갔다" 와 created_at 범위를 찍는다. **그대로 다시 돌리면** 이미 들어간 건은 중복 판정으로 건너뛰므로 이어서 넣을 수 있다.
4. 순서는 **고객 → 품번 → 주문**. 주문은 고객 표를 보지 않으므로 순서가 바뀌어도 되지만, 고객이 먼저 있어야 거래처 화면에서 주문 이력이 바로 붙는다.
5. 로그 `ops-import-<login_id>-<시각>.log` 가 저장소 루트에 남는다(.gitignore 에 패턴이 없다 — 커밋하지 말 것. 고객 이름·연락처가 들어 있다). 끝나면 지우거나 운영 폴더로 옮긴다.

실행 환경: 저장소 루트의 `.env.local` 에 `VITE_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`(ops-subscription.mjs 와 같은 키). service role 이라 RLS 를 지나친다 — login_id 를 꼭 다시 확인한다.

## 3. 되돌리는 법

- **주문**: 모든 이관 행은 `time = "00:00"` 이고 한 번의 apply 는 created_at 이 몇 초 안에 몰려 있다. 로그의 "created_at 범위 A ~ B" 로 `db.deleteExcelOrdersByRange(A, B)`(src/lib/db.js) 를 부르거나, SQL 로
  `delete from payment_logs where user_id = :owner and order_id in (select id::text from orders where user_id = :owner and time = '00:00' and created_at between A and B); delete from orders where user_id = :owner and time = '00:00' and created_at between A and B;`
  (옛 화면의 "엑셀 업로드 묶음 삭제" 가 쓰는 것과 같은 규칙 — fetchExcelUploadBatches 가 created_at 1분 창으로 묶음을 나눈다.)
- **고객**: `delete from customers where user_id = :owner and created_at between A and B and total_orders = 0;` — 이관 뒤 주문이 붙은(total_orders > 0) 고객은 지우지 않는다.
- **품번**: 롤이 하나도 없는 품번만 `delete from products where user_id = :owner and created_at between A and B and id not in (select product_id from stock_rolls);`. 롤이 붙은 품번은 지우면 안 된다(라벨 QR 이 그 품번으로 시작한다).

## 4. 채널 주문 가져오기 (화면, 매일)

주문 관리 › **채널 주문 가져오기**(`/app/orders/import`). 쿠팡 윙·스마트스토어에서 내려받은 엑셀을 올리면 헤더로 양식을 자동 감지하고(바꿀 수 있음), 못 찾은 칸만 사람이 고른 뒤 미리보기에서 체크한 건만 등록한다. AI 를 쓰지 않는다. **같은 판매처·같은 채널 주문번호는 건너뛰고 기존 주문은 바꾸지 않는다**(`orders.channel_order_id` 유일 인덱스, migrations/saas_features.sql). 포장 담당은 쓸 수 없다.

인식 컬럼(`src/saas/lib/channelImport.js` PRESETS):

| 칸 | 쿠팡 윙 | 스마트스토어 | 일반 양식 |
|---|---|---|---|
| 주문번호 * | 주문번호 | 주문번호(묶음) · 상품주문번호 | 주문번호, order no |
| 수취인 * | 수취인이름 · 수취인명 | 수취인명 | 수취인, 받는분, 고객명, 이름 |
| 구매자 | 구매자 | 구매자명 | 구매자, 주문자 |
| 연락처 | 수취인전화번호 · 구매자전화번호 | 수취인연락처1 · 수취인연락처2 · 구매자연락처 | 연락처, 전화번호, 휴대폰 |
| 주소 | 우편번호 · 수취인 주소 | 우편번호 · 배송지(기본배송지) · 상세배송지 | 우편번호 · 주소, 배송지 · 상세주소 |
| 상품명 * | 등록상품명 · 노출상품명(옵션명) | 상품명 | 상품명, 원단명, 품명 |
| 옵션(색상) | 등록옵션명 | 옵션정보 | 옵션, 색상, 컬러 |
| 수량 | 구매수(수량) | 수량 | 수량, 마수 |
| 단가 | 옵션판매가(판매단가) | 상품가격 · 옵션가격 | 단가 |
| 상품 금액 | 결제액 | 상품별 총 주문금액 | 금액, 결제금액, 주문금액 |
| 배송비 | 배송비 | 배송비 합계 | 배송비, 운임 |
| 배송 메시지 | 배송메세지 · 상품별 추가메시지 | 배송메세지 | 배송메시지, 요청사항 |
| 주문일시 | 주문일 | 주문일시 · 결제일 | 주문일시, 주문일, 날짜 |
| 주문 상태 | 주문상태 | 클레임상태 · 주문상태 | 상태 |
| 메모 | 주문자 추가메시지 · 기타 | 판매자 상품코드 | 메모, 비고 |

규칙: 같은 주문번호의 여러 행은 한 주문의 여러 품목으로 합친다. 배송비는 묶음마다 모든 행에 반복되므로 더하지 않고 큰 값 하나만. 금액이 비면 수량 × 단가. 전화번호는 010-1234-5678(안심번호 0503-… 도) 꼴. 문제 행(주문번호·수취인·상품명·주소 없음, 수량 0, 금액 0, 취소·반품 상태)은 빨갛게 표시되고 체크가 풀려 있다 — 보고 켤 수 있다. 등록되는 주문: 상태 접수, 담당자 = 지금 담당자, 출고예정일 = 다음 영업일, 판매처 = 쿠팡/스마트스토어/자사몰, 메모에 "[쿠팡] 주문번호 … · 주문 2026-10-20 09:12". "결제 완료 주문으로 등록"(기본 켬)이면 입금완료 + 입금 기록(총액). 고객은 이름+연락처가 없을 때만 새로 만든다.

알려진 한계: 스마트스토어의 **비밀번호 걸린 엑셀**은 못 읽는다(네이버에서 비밀번호 없이 내려받거나 엑셀에서 비밀번호를 풀어 저장). CSV 는 UTF-8 만 안전하다(EUC-KR 이면 한글 헤더가 깨져 매핑이 안 된다 — xlsx 로 저장해 올린다).
