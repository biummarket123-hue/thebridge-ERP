# 환불 · 반품 · 적립금 업무 매뉴얼 (직원 인수인계용)

> 로하이마켓 ERP 기준. 화면의 버튼 이름을 그대로 표기했습니다.
> 최종 갱신: 2026-07-21

---

## 0. 먼저 이해할 4가지 (이것만 알아도 절반)

1. **환불과 반품은 다른 메뉴입니다.**
   - **환불** = 돈만 돌려줌 (물건 회수 없음) → **정산관리 탭**에서 처리
   - **반품** = 물건을 돌려받음 (재고 복구) → **보관/반품 탭 > 반품**에서 처리
   - 물건도 받고 돈도 돌려줘야 하면 → **반품 먼저, 환불은 그다음** (상황 3)

2. **환불은 2단계입니다.** 직원이 "환불 신청" → 대표가 정산관리에서 **승인**해야 실제 처리됩니다.
   신청만 하면 아무것도 바뀌지 않습니다 (돈·재고·적립금 전부 그대로).

3. **적립금은 자동으로 쌓이지 않습니다.** 구매 시 % 적립 같은 기능은 없고,
   대표가 정산관리에서 **전부 수동으로** 지급/회수합니다.

4. **권한 구분**
   - 출고완료/출고취소, 환불 승인, 반품 되돌리기·삭제, 주문취소 → **관리자(대표)만**
   - 포장 담당자는 주문입력·정산관리 탭이 아예 안 보임 (정상입니다)

## 상황 1. 고객이 "환불해 주세요" (물건 회수 없이 돈만)

### 직원이 할 일 — 환불 신청

1. 주문 찾기: **주문현황 탭**에서 검색하거나, **대시보드 탭**에서 출고완료+입금완료 주문의 **`💸 환불신청`** 버튼 클릭
2. 환불 신청 창에서 입력:
   - 환불 방식: **`💵 현금환불`** 또는 **`🪙 적립금환불`**
   - 현금환불이면 **`🏦 환불 계좌`** 입력 (은행명 / 예금주 / 계좌번호) — 고객에게 꼭 확인
   - 환불 범위: **`전액환불`** 또는 **`부분환불`** (부분환불 가능, 금액은 입금액 초과 불가)
   - 사유 입력 (예: 단순변심 · 불량 · 오배송)
3. **`N원 환불 신청`** 버튼 → 주문이 **환불신청** 상태로 바뀜
4. 여기까지가 직원 역할. 대표에게 "환불 신청 올렸습니다"라고 알려주면 좋습니다.

### 대표가 할 일 — 승인

1. **정산관리 탭** → 목록 상단 필터에서 **`환불신청`** (대기 건수 표시됨)
2. 주문 클릭 → **`🔴 환불 신청 · 승인 대기`** 카드에서 방식/금액/계좌/사유 확인 (계좌는 **복사** 버튼)
3. **`현금 환불`** 또는 **`적립금 전환`** 버튼 → 확인창에서 승인
   - ⚠️ 현금환불의 경우 **실제 은행 이체는 앱 밖에서 직접** 해야 합니다. 앱은 기록만 남깁니다.
4. 잘못된 신청이면 **`✗ 반려`** → 주문이 입금완료로 돌아가고, 반려 사유는 담당자 메모에 `🔴 환불반려:` 로 남음

### 승인하면 자동으로 되는 것

| 항목 | 전액환불 | 부분환불 |
|---|---|---|
| 환불 기록(payment_logs) | O | O |
| 고객이 썼던 적립금 자동 반환 | **O** | **X (반환 안 됨!)** |
| 무료배송권 1장 복원 | **O** | **X** |
| 합배송 그룹에서 제외 | O | O |
| 주문 상태 | `환불` 종결 → 대시보드로 이동 | 정산관리에 계속 남음 |
| **재고 복구** | **X — 환불은 재고를 절대 건드리지 않음** | X |

> **직원들이 가장 많이 헷갈리는 지점:** "부분환불 했는데 고객 적립금이 안 돌아왔어요" → 정상 동작입니다.
> 부분환불에서 적립금을 돌려줘야 하면 대표가 적립금 관리에서 수동 등록하세요 (상황 5).

## 상황 2. 고객이 물건을 돌려보냄 (반품)

### 등록

1. **보관/반품 탭 > 반품** 서브탭 → **"반품 등록"** 에서 주문 검색
   (**출고완료 주문만** 검색됩니다 / 대시보드의 **`↩️ 반품 신청`** 버튼으로도 가능)
2. 품목별로 반품 수량 입력 — **부분 반품 가능**, `전량` 버튼 있음. 금액은 수량 비율로 자동 계산
3. **`↩️ 반품 신청 등록`** 클릭

### 상태 진행 (버튼 순서대로)

```
반품신청 → [🚚 수거중으로] → 수거중 → [📥 반품입고 (재고 복구)] → 반품입고 → [✓ 완료 / 🔄 교환 / 💸 환불신청 연결]
```

- **`📥 반품입고 (재고 복구)`** 를 눌러야 재고가 자동 복구됩니다. **이 버튼을 안 누르면 재고는 안 돌아옵니다.**
- 확인창에 "재고 미등록 N건은 복구 없이 진행"이 뜨면 → 그 품목은 자동 복구가 안 되니 **재고를 수동으로 보정**해야 합니다.
- "⚠ 재고 복구 실패 N건" 토스트가 뜨면 → **재시도해도 복구되지 않습니다.** 재고현황에서 직접 수동 보정하세요.

### 반품입고 후 마무리 3가지

- **`✓ 완료`** — 물건만 돌려받고 끝 (돈 문제 없음)
- **`🔄 교환`** — 상황 4 참고
- **`💸 환불신청 연결`** — 돈도 돌려줘야 하면 여기로 → 상황 1의 대표 승인 절차로 이어짐

> ⚠️ 반품 건 삭제(관리자만)를 해도 **이미 복구된 재고는 되돌아가지 않습니다.** 삭제 전 재고 숫자 확인.

## 상황 3. 반품 + 환불 둘 다 (가장 흔한 케이스)

**순서를 꼭 지키세요:**

1. 반품 등록 → 수거중 → **`📥 반품입고 (재고 복구)`** ← 재고 먼저!
2. **`💸 환불신청 연결`** 버튼으로 환불 신청
3. 대표가 정산관리에서 승인

> 순서를 건너뛰고 정산관리에서 환불만 처리하면 **돈은 나가는데 재고는 안 돌아옵니다.**
> 환불 기능은 재고를 건드리지 않기 때문입니다.

## 상황 4. 교환

1. 반품 흐름으로 **반품입고까지** 진행 (기존 물건 재고 복구)
2. **`🔄 교환`** 버튼 → 교환 보낼 품목과 차액 입력
3. 차액 처리:
   - 고객이 **더 내야 하면(+)**: 원 주문에 미수금으로 잡히거나 적립금에서 차감
   - 고객에게 **돌려줘야 하면(−)**: 환불신청으로 연결 → 대표 승인

## 상황 5. 적립금 지급 / 회수 (대표 전용)

**다시 강조: 자동 적립은 없습니다.** 적립금이 늘어나는 경우는 ① 대표가 수동 지급 ② 환불을 적립금으로 전환 ③ 전액환불·주문삭제 시 자동 반환, 이 세 가지뿐입니다.

### 지급

1. **정산관리 탭 > `🎁 적립금 & 배송권 관리`** 서브탭
2. "혜택 발급" 카드에서 **`💰 적립금`** 선택 (무료배송권도 여기서 발급)
3. 고객명 검색·선택 → 금액·사유 입력 → **`적립금 등록`**

### 회수

- 같은 화면의 **`회수`** 버튼 → "N님의 적립금 M원을 회수하시겠습니까? 잔액 A원 → B원" 확인

### 주의

- **고객관리에 등록된 고객만** 가능. "등록되지 않은 고객입니다" 뜨면 → 고객관리에서 먼저 등록
- 적립금은 **고객 이름 글자 그대로** 매칭됩니다. 닉네임·공백이 다르면 잔액이 딴 사람처럼 분리됨 → 이름 표기 통일 필수
- 내역 확인: 같은 화면 아래 **"적립금 내역"** (전체/적립/사용 필터, 고객 검색, 10건씩)

## 상황 6. 적립금 사용 (주문에서 차감)

**방법 A — 새 주문 받을 때** (주문입력 탭)
- 주문입력 폼에서 적립금 사용액 지정. 잔액·주문총액 한도 내 자동 조정
- 이미 완납 처리되는 주문(방문 결제 등)에는 적용되지 않음 — "이미 완납 주문이라 적립금은 적용하지 않았습니다"

**방법 B — 기존 주문의 미수금 처리** (정산관리 탭)
- 주문 선택 → **`적립금 차감`** (미수금이 있는 주문에만 보임, "차감 가능: 최대 N원" 안내)
- 잔액 초과, 미수금 초과 불가

최소 사용 금액 제한은 없습니다.

## 상황 7. 실수했을 때 되돌리기

| 실수 | 되돌리는 방법 | 권한 |
|---|---|---|
| 환불 신청을 잘못 올림 | 대표가 정산관리에서 **`✗ 반려`** → 입금완료로 복귀 | 대표 |
| 환불을 잘못 **승인**함 | 정산관리에서 환불 취소 ("환불 N원을 취소하고 입금완료 상태로 되돌리시겠습니까?") — 전환·복원된 적립금도 함께 정리됨 | 대표 |
| 출고완료를 잘못 누름 | 출고 취소 → 재고 복구 + 출고 로그 삭제 | 대표 |
| 주문 자체를 없던 일로 | 대시보드의 주문취소 — ⚠️ **결제·출고·적립금 로그가 전부 삭제**되고 복구 불가. 최후의 수단 | 대표 |

## 절대 하지 말 것

1. **Supabase(DB)에서 데이터 직접 수정 금지.**
   - 화면의 결제상태는 `orders.payment` 컬럼이 아니라 **결제 로그(payment_logs) 합산**으로 계산됩니다. DB에서 컬럼만 고치면 화면과 데이터가 어긋납니다.
   - 적립금(credits)도 전체 합산이 잔액입니다. 한 줄만 지워도 잔액이 틀어집니다.
2. **부분환불 후 적립금·배송권이 안 돌아온 것을 버그로 착각하고 임의 조작 금지** — 정상 동작. 필요 시 수동 지급.
3. **엑셀 업로드 주문(시간이 00:00으로 표시)은 임의 수정 금지** — 대시보드 집계 전용이라 건드리면 매출이 틀어집니다.
4. 주문 삭제 시 "적립금 N원 반환 실패 — 정산관리에서 직접 등록해주세요" 토스트가 뜨면 → **꼭 그 자리에서 수동 등록** (나중에 하면 잊어버립니다).

## 자주 묻는 질문 (직원 오해 TOP 5)

**Q1. 환불신청 했는데 왜 처리가 안 되나요?**
→ 신청은 요청일 뿐입니다. 대표가 정산관리에서 승인해야 처리됩니다.

**Q2. 부분환불 했는데 고객이 쓴 적립금이 안 돌아와요.**
→ 정상입니다. 전액환불일 때만 자동 반환됩니다. 필요하면 대표가 수동 지급하세요.

**Q3. 환불 처리했는데 재고가 안 늘어요.**
→ 환불은 재고를 건드리지 않습니다. 물건을 받았으면 반품 흐름(반품입고)을 쓰세요.

**Q4. 적립금 등록이 안 돼요 ("등록되지 않은 고객입니다").**
→ 고객관리에 먼저 등록하고, 이름 표기가 주문의 고객명과 정확히 같은지 확인하세요.

**Q5. 환불했더니 미수금 표시가 사라졌어요.**
→ 정상입니다. 환불은 가격 조정으로 취급되어 미수금이 0으로 계산됩니다.

## 신입 교육용 실습 시나리오 (인수인계 시 이 순서로 시켜보세요)

1. **[환불만]** 테스트 주문 하나 골라 부분환불 5,000원 신청 → 대표 계정으로 반려까지
2. **[반품+환불]** 반품 등록 → 수거중 → 반품입고(재고 숫자 변하는 것 확인) → 환불신청 연결 → 승인
3. **[적립금]** 테스트 고객에게 적립금 3,000원 지급 → 내역에서 확인 → 회수
4. 끝나면 "부분환불 시 적립금이 자동 반환되는가?" 물어보기 (답: 아니오) — 이해도 체크용
